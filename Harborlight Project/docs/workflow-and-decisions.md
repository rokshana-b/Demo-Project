# Workflow and decisions

## Sample issue workflow

`Backlog → Ready → In progress → In review → Done`

A card moves to **Ready** when its scope and acceptance criteria are understandable. Work moves to **In review** when the owner has recorded the result or requested review. Close an issue when the requested outcome is demonstrated or the item is intentionally deferred with a note.

## Demo decisions

| ID | Decision | Reason |
|---|---|---|
| D-01 | Keep requirements and test cases in Markdown | Changes are readable in Git history and GitHub |
| D-02 | Use GitHub Issues for individual work and defects | Makes ownership, discussion, and status visible |
| D-03 | Use tiny CSVs only for example input records | Keeps tabular examples easy to inspect |
| D-04 | Use invented names and example-only contact details | Prevents demo content from resembling real customer data |
