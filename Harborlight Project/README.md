# Harborlight Insurance QA Demo

A fictional project used to demonstrate GitHub documentation, Issues, labels, milestones, and Projects. All names, policy numbers, people, dates, and results in this repository are invented. Do not use this sample data for real insurance decisions.

## Project at a glance

Harborlight Mutual is a made-up insurer piloting a small personal auto quote experience. The demo team is validating quote entry, discounts, document handling, and basic policy review. This repository contains planning and sample QA artifacts; it does not contain a real application or automation framework.

## Repository map

| Folder | Contents |
|---|---|
| `docs/` | Project brief, workflow, glossary, and GitHub demo setup |
| `requirements/` | Fictional business requirements and user stories |
| `test-plans/` | Test approach, scenarios, and regression checklist |
| `test-cases/` | Manual test cases and traceability |
| `test-data/` | Small, fabricated CSV samples |
| `reports/` | Example execution summary |
| `.github/ISSUE_TEMPLATE/` | Bug, user story, and task forms |

## Suggested demo flow

1. Upload this repository and show the README and linked documents.
2. Create the labels and milestones listed in [`docs/github-demo-playbook.md`](docs/github-demo-playbook.md).
3. Open a few Issues from the included backlog examples in that playbook.
4. Add those issues to a GitHub Project and move them through the sample workflow.
5. Show a requirement change and its Markdown diff in a commit or pull request.

## Safety and data note

Every record uses obviously fictional values and reserved example domains. The records are for interface demos only.
